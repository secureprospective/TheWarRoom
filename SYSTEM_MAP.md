# System Map

A feature directory: find any feature in two hops. Current as of 2026-10-20 (`main` 6738d82b).

**How to find things**
1. Find the feature in the table below; the slug in the first column is its name everywhere else.
2. The backend entry is a root file in `package main`, where the Wails-bound `App` methods live. Logic sits in the `internal/` packages beside it.
3. Frontend code is under `frontend/src/app/<dir>/`, with its tests colocated as `*.test.ts(x)`.
4. To find a file's feature, look it up in `docs/architecture/placement.tsv` (every root `*.go` file and every `internal/` package, one row each).
5. Layers, the IPC surface, data, external services and the native league are written up at length in `docs/architecture/system-narrative.md`.

Paths are relative to the repo root. `frontend/src/app/` is shortened to `app/`. A `*` is a glob. Root test files are listed in full in the manifest.

## Where new code goes

Wails keeps calling **one** `App` object, so the frontend never churns. A root file is a **thin
adapter**: the bound method, its wire shape, and a call into the feature. The feature's real logic
lives in `internal/app/<feature>/` (the slug from the table). The root keeps only composition:
startup, shutdown, locks, logging and the binding adapters.

- A new root `*.go` file needs a row in `docs/architecture/placement.tsv`, and the root count may
  not rise above `docs/architecture/root-go-baseline.txt`. Both are checked by `make lint` and CI
  (`scripts/check-placement.sh`, `scripts/check-root-ratchet.sh`).
- A new `internal/` package needs a manifest row and a mention in this table's row for its feature.
- A new feature needs a row here before its first file lands.
