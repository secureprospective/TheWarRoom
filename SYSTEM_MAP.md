# System Map

A feature directory: find any feature in two hops. Current as of 2026-10-20 (`main` 6738d82b).

**How to find things**
1. Find the feature in the table below; the slug in the first column is its name everywhere else.
2. The backend entry is a directly bound API in `internal/app/<feature>`, over an unbound adapter in `internal/composition` (the root holds only `main.go`). Comms uses the new feature API template; shared state and locks live in `internal/app/core` (`docs/architecture/feature-extraction.md`).
3. Frontend code is under `frontend/src/app/<dir>/`, with its tests colocated as `*.test.ts(x)`.
4. To find a file's feature, look it up in `docs/architecture/placement.tsv` (the root `main.go` and every `internal/` package, one row each).
5. Layers, the IPC surface, data, external services and the native league are written up at length in `docs/architecture/system-narrative.md`.

Paths are relative to the repo root. `frontend/src/app/` is shortened to `app/`. A `*` is a glob. Composition test files live beside their code in `internal/composition`.

## Where new code goes

Wails binds the legacy App plus each extracted feature API. App has a named core.State field;
shared state/locks live in core and feature-owned Host ports prevent reverse imports. New
features follow the Feature API template in `docs/architecture/feature-extraction.md`.

- A new root `internal/composition/*.go` file needs a row in `docs/architecture/placement.tsv`, and the root count may
  not rise above `docs/architecture/root-go-baseline.txt`. Both are checked by `make lint` and CI
  (`scripts/check-placement.sh`, `scripts/check-root-ratchet.sh`).
- A new `internal/` package needs a manifest row and a mention in this table's row for its feature.
- A new feature needs a row here before its first file lands.

## Rules CI enforces

| Guard | Failure and fix |
|---|---|
| Root-file ratchet (`make placement`) | Root `internal/composition/*.go` count exceeds `docs/architecture/root-go-baseline.txt`: extract logic and tests into their feature; lower the baseline as files leave, never raise it to hide growth. |
| Placement (`make placement`) | A root file or internal package is missing, duplicated, stale or unindexed in `docs/architecture/placement.tsv`: correct its feature row and this map; remove obsolete paths. |
| Decision syntax (`make boundary`, in `make lint`) | New/changed decision-bearing functions in composition/core fail against `docs/architecture/boundary-adapters.tsv`; reviewed adapters are frozen, legacy core policy is explicit debt, and removal requires tightening the allowlist. This is a syntax ratchet, not semantic proof; review is still required. |
| Import boundaries (`make lint`, `.golangci.yml` depguard) | Non-app internals cannot import `internal/app` or root; services cannot import root or any Wails package. Features can import their own subtree (including test helpers) and the explicit shared set **`internal/app/report` and `internal/app/season`**, plus catalog where declared, not siblings. Core imports no features/Wails; features never import core. Inject dependencies at root or move shared view models to season and wording to report. Declare a newly extracted feature's own subtree in depguard; undeclared features default to shared-only imports. Existing engine, transport and store rules still apply. |
| Binding freshness (`make bindings-fresh`) | `scripts/check-bindings-fresh.sh` regenerates in a private temporary source copy and diffs all of `frontend/wailsjs`, without overwriting local edits. Run `make bindings`, review and commit the generated changes. Both `make verify` and CI's required verify/checks job run this guard. |
| Binding manifest (root Wire/Manifest tests) | Every reflected method on App and comms.API must match `testdata/bindings/manifest.txt`; every non-App method needs a package-level catalog entry. No promoted core helpers. |
| Frontend transport (`make frontend-transport`) | Generated feature imports/models and window.go feature access stay in that feature's api.ts. Comms has no legacy main/App access. |
| Wails version (`scripts/check-wails-version.sh`) | CLI differs from `go.mod` (currently v2.13.0): install the Wails CLI at the module's exact version (the script prints the command). CI installs that version before checking bindings. |

Binding generation uses Wails' `bindings` build tag, not the desktop app: no GTK, display,
frontend install or app startup is required. Its private `TMPDIR` avoids colliding with another
worktree's fixed-name generator executable; temporary copies live under the caller's TMPDIR (or /tmp) and are cleaned on exit. The normal frontend checks still run in CI.
Deliberate engine→app, service→runtime, sibling-service imports and a hand-edited TypeScript
model each failed their guard before being reverted (Codex §M3).

Move handoff/withdrawal, evidence refresh/watch scheduling and roster-verdict rebasing policy
live in `internal/app/platform`.
Composition retains raw cross-feature observation assembly and release/contract revalidation adapters.
