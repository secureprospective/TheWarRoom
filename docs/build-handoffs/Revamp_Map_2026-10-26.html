The 16 parts

1 · Command spineXL · do first

What: the pipe every action runs through. A button, CLI line, chat, AI helper or server request all land on the same named command.

Today: four lists that have drifted apart. The server accepts only 42 of the native commands, and the CLI/MCP have just 3 generic verbs. Bugs: the "change engine parameter" button can never run (dispatch demands GM, the command is admin-only). A catch-all command silently drops actions. History logs "pressed", not "done".

Better: one registry in Go that runs commands, with every door generated from it. The UI keeps a small list for screen-only actions. CI fails the build if a button has no command.

Why: commands make CLI, chat and AI first-class. One standard keeps every door telling the same truth.

2 · App boundaryXL

What: where the real work lives: refresh, trade plans, valuation runs.

Today: stuck inside the desktop's startup wiring (composition, 7k lines + 26.7k test lines) and one giant shared State with many locks.

Better: small per-feature services that know nothing about desktop or transport. Desktop, server and CLI all call them. Tests move with the behaviour.

Why: the server owns the league, every door must share one brain, and a part can only be rebuilt in isolation if it lives in one place.

3 · Frontend data handlingL

Today: 30 stores each re-write loading flags, late-reply protection, error handling and refresh, plus three different polling styles.

Better: one shared "read this" tool, written and tested once. Each screen just asks for what it needs.

Why: no copy of the same bug in 30 places, no stale screens, safe league/account switching once owners connect.

4 · Storage + league recoveryXL

Today: three databases with three ways of changing their layout, one of them unversioned. The history store does five jobs. Recovery is spread across backups, transfer and restore scripts.

Better: one versioned upgrade path per database, and a split history store. A standalone rosters + contracts restore point, a per-league recovery log, and a tested "stand the league back up" command. Steps: restore rosters/contracts → check cap totals → commish signs in → owners sign in → attach history.

Ruling: the league is rosters + contracts. History is secondary.
5 · Player identityL/XL

Today: the MFL player ID is the identity everywhere (165+ files). Other sources get matched to it, and bad matches already happen.

Better: our own player ID as the master, with MFL, GSIS, ESPN, Sleeper and CFBD as stored links. Existing MFL IDs map one-to-one, so nothing stored today breaks.

Ruling: we run our own system. Ownership is keyed by side + player for the mirrored league.
6 · Native league core splitXL · 6 sessions

Today: one 21.6k-line commissioner package with the thinnest tests. Everything goes through one switch and one bundled arguments type.

Better: split into domains, one session each: Market (trades, bids, waivers; first, to prove the pattern) · Governance + people · Rules (absorbs the old rulebook) · Draft · Competition (scoring, standings, schedule, lineups, playoffs) · Season. A small shared core keeps old records readable.

Why: this is where rosters and contracts change, and the default league modes build on it.

7 · Valuation + scoringXL · heavy tinkering

Today: six unnamed ways to value a player. Settings for the removed six-layer engine are still editable but do nothing. Prior seasons get rescored under current rules. The Lab retrains at every startup and stops valuing on Jan 1, 2027.

Better: named, versioned value products, native-first. Remove the dead settings, train once and load fast, and rewrite the spec to match reality.

Why tinkering: there's no agreed target yet. "Right" is judged against real outcomes, not unit tests. Many hand-tuned settings, new native inputs, two league modes and per-position behaviour all shift the numbers.

Rulings: lean native · the Lab leaves the app and becomes an R&D bench for data fields, never direct reporting · a small 2027 stopgap until then.
8 · Stats pipelineL

Today: nflverse (deep, not live), ESPN/Yahoo live (box-score level), and players, injuries and NFL schedule from MFL. Ingestion mixes MFL league data with football facts.

Better: a first-class native stats feed, split into MFL import vs football facts. One standard result per feed, with freshness shown. The saved-download fingerprint chain stays intact.

Rulings: MFL data is unreliable, so it's never the source of football facts · widest stat suite possible (QB hits, first downs, IDP, play-level, snaps, live, corrections) · compare providers first, Christopher picks.
9 · MFL reference appL · low attention

Today: a full second engine: an imported MFL copy, a what-if copy, plans watched against MFL, MFL rule checks. It shares command names with native but they mean different things.

Better: fence it into its own labelled area with its own names (mfl.*). No new features; share only the pure math. Freeze it.

Ruling: MFL import keeps working, but it gets less attention than native.
10 · Server/client transportL

Today: 19 routes, with four doors for the same action. A hand-typed 42-command allowlist. The client imports the server's own code. Error formats differ by door.

Better: a shared protocol package and one league command door generated from Part 1. Split the client. One error format: plain words for owners, stable codes for experts.

Ruling: non-technical users come first, and experts are never limited.
11 · Accounts + securityL

Today: a strong core (hashing, TOTP, scoped AI tokens, a shared writer that stops revoked users). But there are two sign-in worlds, an unversioned schema, and security code tied to league details.

Better: one simple sign-in path (invite → password → scan QR), a versioned schema, and a small security↔league check. Split membership from succession. No secrets anywhere in logs.

12 · OperationsL

Today: encrypted and verified R2 backups, TUF-signed updates, guarded transfer. But install, serve, upgrade and restore are four separate paths across Go and ~1,600 lines of shell, and the real-world drills haven't been run.

Better: one deployment state machine where Go does the checks. Backups feed Part 4's recovery. Guided install, and plain status like "Backed up 4 min ago ✓". Run the drills.

13 · ScreensL · tinkering

Today: two apps in one window. The real hosted native app is buried in a commissioner folder. The shell does feature work, and Market routes five other pages.

Better: the hosted native app becomes the main app. Features own their screens, the shell is just the frame, and there's one route table.

First step: a screen scorecard. Tools rate every screen on: every button a command · speed and bundle size · minimal code · plain language · no dead space (screenshots) · accessibility · all states shown.
14 · Read screens + visual systemM each

Screens: Now, Race, Archive, Research, Comms, Reports, Counterparties, Market analytics.

Better: a shared report kit (moved out of draft), one refresh policy, and clean tokens and cards. The specimen page is the reference. The hold timer is fixed to 600 ms. Lab figures switch to native values or get dropped. Archive goes first to prove the pattern.

15 · DetachM

Moves out of the shipping app: Lab + labcompile, cmd/fit, labparity → research zone · fixtures, practice/hostedfixture → dev tools · the pi-durable experiment and normalize.py → out of docs.

Keeps: FixtureProvider + snapshot.json (ruling), the specimen page, the wire-contract tests.

Better: two zones. CI blocks the app from importing tools.

16 · Docs + gatesM · ongoing

Stale today: Go version, a removed RESUME, UI spec revision, the pre-push claim, the SYSTEM_MAP limit target, the six-layer engine in North Star and the README.

Gate gaps: release-tools is outside the required check, coverage never runs, tool tests run nowhere, the 195 wire files have no list, composition tests run at 3.7:1.

Better: every doc labelled, and each session fixes its own docs. New gates: every button has a command, the app never imports tools, scorecard thresholds.

Rulings from this session

  • The league is rosters + contracts. Recovery restores those first, and each league keeps a recovery log.
  • Default mode 1: 32 teams, 16 AFC + 16 NFC. Each side has its own full player pool (a player is owned once per side). No cross-side moves, normal cross-side schedule, side champions meet in a final.
  • Default mode 2: a modified version of the current Legacy league, to be discussed later.
  • Lean native. The MFL harness gets less attention but keeps working.
  • The Lab leaves the app. It becomes an R&D bench for data fields, with a small 2027 stopgap until then.
  • Widest stat suite possible, fast and reliable. Compare providers; Christopher picks.
  • Non-technical first, experts never limited.
  • Screens get a scorecard that rates them against the build philosophy.
