## PASS A — ENGINE + RUBRICS + COMPOSITION + HARNESS

### MAJOR
None found.

### MINOR

1. **L5 does not re-validate `scoutingAdjusted` as finite.** `ApplyCapScaling` gates `leagueCap`, `salary`, `coldCeiling`, `hotFloor` but not the accumulator it scales; a non-finite `scoutingAdjusted` would pass into `AdjustedScore`. Not reachable today (upstream layers all NaN-guard), but L5's own fail-loud contract is weaker than every other layer's.

2. **CapScaling engine gate is asymmetric with the decay gate.** `ApplyDecay` re-validates `decayRate ∈ [0,1]` defense-in-depth; `ApplyCapScaling` does not re-validate `coldCeiling ≤ hotFloor` or non-negativity. Composition guards both, but inverted/poisoned tiers would silently mis-tier rather than fail loud.

3. **Boundary numeric-range gaps.** `Validate` range-checks [0,1] sub-signals and `collegeShare`, but only finite-checks `RAS` and `BasePoints` — no `RAS ∈ [0,10]`, no `BasePoints ≥ 0`, no `Age` upper bound. Downstream clamps prevent score corruption (values saturate), but this is inconsistent with the fail-loud contract applied to the [0,1] signals.

4. **DT cushion constants duplicated without the drift callout.** `dtCushionRAS=8.00` / `dtCushionDecline=0.90` in `dt.go` mirror `cushionGuard(PosDT)` in `defaults.go`. The `dtPeakAge` mirror is explicitly flagged as accepted single-spec duplication; the cushion pair is not. If `cushionGuard` is re-tuned and `dt.go` is not, the L3 decay window and L4 age-trajectory window desync silently (SL-021 broken on the seam).

5. **EDGE resolution is a caller contract, not enforced by `Assemble`.** `Assemble` does not call `ResolveRubricPosition`; only `RankRookies` does before calling assemble. A future caller that skips resolve would score a pass-rush-primary LB as an LB (wrong rubric AND wrong calibration). Low probability now, but a fragile seam.

6. **`curve` NaN-backstop is uneven.** `Scurve` and `SL019` guard non-finite input; `Present`, `SubSignal`, and `Interp` do not — they rely on the caller wrapping the composite in `Scurve`. All current rubrics do wrap, so defended in practice; the assumption is undocumented for future rubric authors, and `SL019`'s own comment sets the bar higher than these helpers meet.

7. **`SL019` does not range-check `strength`.** Unlike `ApplyCushionGuard` (which disables on `declineFactor ∉ [0,1]`), `SL019` trusts `strength` (bounded today at 0.30/0.35 constants). A future `strength > 1` would let `modulated` exceed 1.0.

### IMPROVEMENT

1. **Duplicated `finite` helper.** `composition.finite` (playerspec.go) and `engine.finite` (finite.go) are identical. Forced by unexported visibility today; an exported `engine.Finite` would collapse them (M1). Flag, don't act now.

2. **Per-player calibration re-read.** `Assemble` reads calibration from store per player by design; the cache-by-position opportunity documented in the comment is unrealized in `RankRookies` (the only caller that ranks a full set).

### NOTE

1. **Stale case-count / "runs today" doc drift.** `validation.go` comment says "12 cases 3A..3L" and "Today only 3L runs"; `RunValidationSuite` doc says "evaluates all 12 cases"; `cases.go:3084` correctly says "13 architectural cases in 3A..3M". Multiple counts in flight — `cases.go:3084` is canonical.

2. **RB weight comment is garbled.** The weights (0.35/0.20/0.30/0.15, sum 1.00) are correct; the prose explanation is unreadable.

3. **`CapReader.GetSalaryCap()` returns no error** by design; a store-level read failure mis-attributes as a missing value. Documented; worth knowing when debugging a real rulebook outage.

## PASS B — STORES + DB + PRIMITIVES

### MAJOR

1. **`playerid.New` accepts signed numeric strings and emits non-canonical corrupt IDs.** `strconv.Atoi` accepts optional sign (`"+99"` → 99, `"-5"` → -5); the subsequent `strings.TrimLeft(trimmed, "0")` only strips `0` runes, so the sign survives: `"+99"` → canonical `"0+99"`, `"-5"` → `"00-5"`. Two wire/DB values for the same player (`"99"` → `"0099"` vs `"+99"` → `"0+99"`) then fail to match in the cross-reference join — the exact silent data-integrity failure AD-06/RISK-003 exists to prevent. Same gap in `schema.Validate`. Real-world probability is LOW (MFL emits unsigned IDs), but the validation contract is broken. Fix: reject anything not matching `^[0-9]+$` (or check `n >= 0 && trimmed[0] != '+'` after Atoi).

### MINOR

1. **`state.ApplyContract` does not reject NaN/Inf salaries.** Checks `AnnualSalary < 0`, but NaN compares false to everything, so NaN passes validation and persists into the REAL column. `params.validateOverride` guards this explicitly; `state` does not. Inconsistent finite-check across the two stores.

2. **`state.ApplyContract` validation is inconsistent across fields.** Rejects negative `AnnualSalary`/`AdjustedSalary`/`ContractYears` but not negative `ExpirationYear`. A nonsense expiration year lands silently.

3. **`effectiveSalary` conflates "unset" with "set to $0".** `AdjustedSalary > 0` decides whether an adjustment exists. Schema seeds `adjusted_salary=0` as "never adjusted" sentinel, so a legitimate B7 adjustment to exactly $0 is indistinguishable from "never adjusted" and falls back to base salary. Real semantic edge case for $0 restructures.

4. **`state.Player` can nil-deref on index/snapshot drift.** `s.franchises[fid].Players` after `byPlayer[mflID]` returned `fid`; if the two maps desync, `franchises[fid]` is nil and `.Players` panics. Invariant holds today (both built/swapped together in `load`), but a `fs, ok := s.franchises[fid]; if !ok` guard would make it defensive.

5. **`rulebook.Versions` can report a stale `Active` flag.** Reads `activeVersion` and iterates `rulebook_versions` as two unlocked queries; a concurrent `Promote` can change the active pointer between them. Cosmetic (audit surface only), but not point-in-time consistent.

6. **`rulebook.Reload` reads `s.src` without a lock.** `s.src` is set once in `Initialize` under `wmu`. Safe in practice (startup ordering) but technically a data race if Initialize and Reload ever overlap.

### IMPROVEMENT

1. **`boolToInt` duplicated** in `params/helpers.go` and `state/helpers.go` (M1). Stores can't import each other (depguard), so a shared `internal/sqlutil` is the only dedupe path — 5 lines, probably not worth it, but worth a conscious decision.

2. **`execPlayer` signature is a misread trap.** `mflID` sits between `query` and the variadic `setArgs`, so call sites read as if `mflID` is a SET value. Putting `mflID` last (or a small builder) removes the hazard.

3. **Inert "eliminated source" fields in live structs.** `internal/scouting/types.go` carries `PFFGrade`, `DraftNetwork`, `RSPQualitative`, `SharpFootball`, `IDPShow`, `IDPGuru`, `DynastyNerds` — populated by no fetcher. Honest about being dead; a tracking reference (ticket/ADR) on each would stop them drifting into accidental use.

### NOTE

1. **`rulebook.Reload` bypasses `wmu` by design** (writes only candidate version, never active pointer). The `wmu` doc-comment omits Reload; a one-line note explaining why Reload is exempt would stop a future maintainer from "fixing" it.

2. **`buildURL` emits non-deterministic query-key order.** Ranges a map; harmless to MFL but makes URL logging unstable.

3. **Confusing near-homonyms across packages.** `domain.PlayerRecord.ContractYear` ("final contract year") seeds `state.PlayerState.ExpirationYear`, while `state.PlayerState.ContractYears` ("years remaining") is seeded 0. The mapping is correct and commented, but the names invite the wrong intuition.

## PASS C — INGESTION / DATA PIPELINE

### MAJOR

1. **[MED confidence] `madden/fetcher.go` `fillRatings` — latent silent-zero on JSON `null` rating (M3 violation).** `json.Unmarshal([]byte("null"), &n)` leaves `n=0` and returns no error (Go spec). The string-skip guard is `if len(val) > 0 && val[0] == '"' { continue }` — a `null`-valued `_rating` field is neither string nor number and passes through as a silent `0`. Madden is the **0.60-majority K signal** (DECISION-011), so the blast radius is a whole position. **Verify first:** `grep '"[^"]*_rating": null'` on a cached EA response. If nulls occur, add `bytes.Equal(val, []byte("null"))` to the skip branch. If they never occur, downgrade to NOTE.

### MINOR

1. **`madden/fetcher.go` `fetchAll` — unbounded total accumulation.** Each page is byte-capped (`maxPageBytes`), but `all = append(all, p.Docs...)` has no total cap; the loop terminates only on `offset >= p.Count` or an empty page. A hostile or schema-shifted endpoint reporting a huge `Count` would grow `all` unbounded. Add a total-docs or total-bytes ceiling (M13).

2. **`touchshare/fetcher.go` — negative `offense_snaps` silently skipped.** `if snaps <= 0 { skip }` treats negative snap counts (data corruption) the same as a legitimate 0-snap inactive game. Negative is implausible but is corruption, not inactivity — should fail loud (M3).

3. **`collegeshare`/`collegedefense` team attribution assumes consistent team strings across category calls.** `foldRow` keys totals on the current row's `r.Team`; `emit` reads `teams[p.team]` (the player's first-seen team). If CFBD reports a different team string for the same player across `receiving`/`rushing` or `defensive`/`interceptions`, a player's stat folds into one team's bucket while the share denominator is read from another — silent mis-attribution.

4. **`veteranfilm/accumulate.go` `loadFTN` — a header-only/empty FTN season is silently treated as "no charting".** Unlike the buffered CSV fetchers, there is no `errEmpty`-style guard per season; an empty FTN returns an empty map. Only the aggregate empty result fails loud in `Fetch` — a single season's truncated FTN is invisible.

5. **`internal/ingestion/cfbd.go` `FetchCFBDCategory` — `category` spliced into the URL unescaped.** `category` is a package constant today, so not live-exploitable, but it is an injection-shaped seam. Use `url.Values` or `url.QueryEscape` for the query build (M15).

6. **`extcsv.go` `streamCSV` — over-cap at a row boundary surfaces as a CSV parse error, not the over-cap error.** When the `LimitedReader` EOFs mid-record, `r.Read()` returns a parse error before the `lr.N == 0` over-cap check is reached. The read still fails loud (good), but the diagnostic points at "malformed CSV" instead of the real cause (over cap). Check `lr.N == 0` first inside the read-error branch.

### IMPROVEMENT

1. **`optFloat` duplicated verbatim in `ras/fetcher.go` and `pfrcoverage/fetcher.go` (M17).** Both define identical missing-is-nil / malformed-fails-loud logic. `extcsv.go` already hosts `IntCell`/`FloatCell`; add a sibling `OptFloatCell` (missing-is-nil) there and have both fetchers call it.

2. **Drop-ambiguous loop copy-pasted three times** across `ras`, `pfrcoverage`, `madden`. `collegeshare`/`collegedefense` already share this via `ingestion.EmitDropAmbiguous`. The pfr-keyed CSV fetchers share an almost-identical Fetch skeleton; a `EmitDropAmbiguous`-style helper with a row-build callback would retire the duplication.

3. **`cfbd.go` `CFBDInt`/`CFBDFloat` parallel `extcsv.go` `IntCell`/`FloatCell`.** Same missing-is-zero / malformed-fails-loud rule, different input shape. The parse core could be a shared `parseCount`/`parseFractional` callable by both seams.

### NOTE

1. **Collision policy is split.** `ras`, `pfrcoverage`, `collegeshare`, `collegedefense`, `madden` all drop-ambiguous; `touchshare` fails loud on the same shape. Both choices are individually documented and defensible, but the split means a future reader cannot predict the policy from the pattern. Worth a canonical rule in the codex ("drop-ambiguous is the default; fail-loud only where double-count is unavoidable") or confirm touchshare should switch.

2. **`agetrajectory/fetcher.go` `errEmpty` wording drift.** Text says "source resolved zero birth dates" but the guard fires after `gsis+birth_date` filtering — it actually means "zero rows survived the filter."

3. **`schooltier/fetcher.go` `classifyFBS` — exact conference-name string matching.** "SEC"/"Big Ten"/etc. matched literally; a CFBD label change (e.g. "Big Ten Conference") misclassifies a whole conference to GoF with no error. Verified live today; a single integration test pinning the expected set would catch drift.

4. **`veteranfilm/accumulate.go` `rate` trusts caller for `denom > 0`.** Correct given the floor defaults (30/100), but `Fetch`'s `recvFloor`/`passFloor` are parameters — a caller passing 0 yields `0/0` NaN with no guard. Either document `floor >= 1` on the function or add `if denom == 0 { return 0 }`.
