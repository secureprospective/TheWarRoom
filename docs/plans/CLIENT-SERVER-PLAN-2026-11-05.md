# Client/server governing plan — 2026-11-05

**Final plan; implementation gates are not yet passed.** Christopher's [rulings](../audit/CLIENT-SERVER-RULINGS-2026-11-05.md) and his 11-05 adoption of **all** of [Tom's changes](../audit/CLIENT-SERVER-TOM-SECOND-OPINION-2026-11-05.md) govern. This replaces Sol's recommendations (removed 2026-11-09; in git history); the inventory (removed 2026-11-09; in git history) is baseline evidence, not proof of this target. R1–R7 below mean the client/server rulings, not the older engine rulings.

## Target and fixed boundaries

| Boundary | Governing choice |
|---|---|
| Runtime | One always-on Go server, one process owning both SQLite files; thin Wails, same React PWA, CLI/MCP. Complete the existing hosted path, not a new backend. No embedded desktop authority, sync layer, Postgres, Redis, Litestream or WebSocket. |
| Hosting | UPS-backed laptop, unprivileged Alpine Proxmox CT, OpenRC; local-disk SQLite WAL/FULL/foreign keys, bounded readers. One serialized authority writer; accounts share its transaction/admission boundary. Cloudflare Tunnel verifies origin TLS; no public DB/admin port. |
| Solo (R1) | Desktop only; the identical client code path points at the same server binary installed locally as an OS service. One installer explicitly offers **“I play solo”**; no silent provisioning. Loopback-only self-signed TLS generated by installer and pinned by the client, never disable verification. |
| Contract | Reuse `runNative`, `commandcatalog`, nativegen, `leagueservice`, `serverhttp`, `serverclient`, CLI/MCP. One typed command/read catalog and hand-written Raw validation; generated schemas do not grant permissions. Keep preview, confirmation, expected revision, durable receipts and scoped AI permissions. |
| Authority (R5a) | Native ledger wins; MFL is import/reference only. No MFL writes or automatic replacement of native decisions. No source-based league modes; imported settings remain ordinary editable settings. Server time decides deadlines. |
| Authentication (R2, R5b) | Same-origin browser UI/API: Secure, HttpOnly, host-only SameSite cookies, session-bound CSRF and exact Origin checks for unsafe requests; CSP and Fetch Metadata defense. Desktop/CLI retain keys outside WebView. Reject ambiguous cookie+bearer auth. TOTP optional for everyone, commissioners included; choosing no TOTP does not bypass authorization or confirmation. Security review before real owners. |
| Offline | Static shell/preferences and visibly disconnected read-only in-memory readings only. No persistent private cache, offline authority, queued writes or automatic replay. Cold offline launch explains connection need. Unknown mutation outcome is resolved by durable receipt before retry. |
| Routine operation (R7) | Automatic startup, collectors, backup, update and health. Human input only for first-time key setup and destructive restores; do not introduce routine console recipes. Normal product confirmations and explicit solo installation choice remain. |

## Two files and recovery (R4, R6; Tom §§1–2)

| File / recovery member | Contents and policy |
|---|---|
| Authority SQLite | Leagues, complete league events/history, accounts, plans, audit chain, receipts/checkpoints and admission state. Full consistent encrypted recovery set every **5 minutes**; measured capacity replaces current 512 MiB uncompressed / 128 MiB ciphertext caps as necessary. Do not assume small means zero writer stall. |
| Evidence SQLite | Raw archive, observations, identities, provenance, input manifests and newly computed model outputs. Durable evidence retained in full; only decoded in-memory generations/seasons evict. No copied model_scores/run_scores: recompute on server. |
| Evidence recovery | Existing content-SHA objects uploaded once, encrypted before storage, verified by read-back; daily evidence manifest, not a five-minute full evidence-file upload. Preserve observations, identity and fetch/source chronology as well as raw bodies; demonstrate their reconstructible recovery mapping. No new backup tool or second authority. |
| Target setting | R2 **or local folder**, same age encryption, integrity/coverage checks and retention. Solo does not require R2. Coverage checks the configured target; R2 deployment pauses league actions during a sufficiently long outage. Local-folder backup is not off-host disaster protection. |
| Coverage | Preserve 14-minute uncovered write cutoff and post-writer-wait coverage check for the 15-minute acknowledged-authority RPO. Restart remains paused until coverage is established. Daily evidence manifests alone do **not** prove recoverability of newly referenced evidence: step 2 must prove compatible authority checkpoints + verified evidence objects/manifests; otherwise stop, do not relax RPO. |
| Restore | Matched authority set + evidence manifest/objects + binary/configuration/release metadata; validate digests/checkpoints, rebuild derived outputs, revoke restored sessions. Measure complete off-host RTO **≤4 hours**, including spare host provisioning, keys, download, tunnel and owner access. Keys off-server with deputy custody. No raw live DB/WAL copying or upload-ack-only success. |
| Migration/rollback | Backup-API consistent snapshot, read-only version preflight, verified pre-migration backup, transactional migrations and monotonic release stamp. Refuse newer/unsupported files unchanged. Rollback restores matched binary/data/config under writer exclusion; no promise of lossless downgrade after new writes. |

## Updates, queries and collection

| Area | Implementation constraint |
|---|---|
| Invalidation | Existing SSE, HTTPS commands; topics per league: **`ledger-public`, `franchise:<id>-private`, `scores`, `values`, `clock`**. Authorize subscriptions and each notification; private-only changes emit no public topic/timing signal. No ledger payloads, private global counters, per-reading dependency graph or opaque recipient-view-revision framework. Active queries refetch on their topic; inactive entries become invalid. |
| Browser stream | Plain same-origin **EventSource** with cookie auth; league and protocol version in path, no query tokens or custom bearer headers. Preserve native credential adapter. One shared stream per session/active league, bounded consumers, session rechecks/heartbeat, revoke/close and reconnect reread. Restart epoch fences stale cache. Measure existing 250 ms detection before replacing it with coalesced post-commit/publication wakes; preserve subscribe/read race safety and bounded reconciliation. |
| Read ownership | Extend `frontend/src/app/data/query.ts`, not another cache/library. Session-owned accepted immutable readings, in-flight dedup, response fencing, selectors. Keys cover server/epoch, account/auth generation, league/franchise/view, command/version and validated args. Bound inactive entries (start at 32) and measured bytes, active shapes/pagination; clear private state on logout/revoke/switch and reauthorize after sleep. Stale/disconnected views cannot enable authoritative actions. Mutation receipts immediately invalidate related topics. |
| UI lifetime | Home tiles publish independently. Pool refresh becomes an explicit effect/job then pure read before shared retention. Retain only edit/draft/scroll/dialog state outside the read owner; delete duplicate result maps and both hidden War Room mounts after preservation tests. |
| Server jobs | Relocate existing collectors, identity/directory/photos, due worker and `appvalue.Preparation` into server lifecycle, not a nested desktop App. One bounded worker scope/provider; coalesce fetches, timeouts/backoff/Retry-After, no overlapping scope refresh. Reads/writes outrank backfills; compute outside writer, publish only current inputs. Restore authority first, bounded warming later; independent screens work while derived views say Preparing. |
| Source rules | Preserve per-stat **nflverse > ESPN > Sleeper**, missing≠zero, last-good source/as-of/reduced labels and correction replay. Initially preserve ESPN 1-minute busy/5-minute idle + 10-minute final reread, nflverse 20-hour open/30-day closed due gates. MFL discovered host, one server-wide 2 req/s burst-1 limiter, endpoint rules; coalesce only matching season/league/credential scope, never share private responses across owners. |
| MFL review banner (R5a) | Configured reference poll checks about hourly using digest/last-transaction ID versus last confirmed import, never the once/day players endpoint for detection. Existing status reading holds `import_available{since, summary}`; existing SSE invalidates it. Solo owners and hosted commissioners see **“MFL has changes since your last import — Review”** → existing preview → confirmed ledger change. No new channel, OS notification, email or automatic import. |
| Updates | One OpenRC-run update job for the CT; existing TUF verification → admissions pause → verified snapshot → writer exclusion → migrate/activate → readiness → fresh backup → resume; matched-state rollback on failure. No separate privileged daemon. Same server payload in packaging adapters; existing verified desktop updater, later Flatpak packaging trust without competing updater. |
| Delivery/status | Same React assets and contract; hashed static assets only in service worker/CDN, never private `/v1` results; no-store API, safe reload boundary/version floor. Extend existing serverstatus/private bounded logs: latency, writer/backup stall, feed/job age, stream load, memory, WAL/disk and checked coverage. Distinguish liveness/read readiness/write readiness/derived freshness; actionable alerts, no email. |

## Acceptance and unresolved tensions

| Item | Required disposition |
|---|---|
| Preservation / deletion | Each slice records complete affected handwritten production LOC/characters before/after separately from generated output, tests/docs and total tracked tree. Hold/shrink production where replacements permit; relocation is not shrinkage. Preserve tests/privacy copies/rule math/provenance. If a safe slice cannot meet the agreed budget, stop for ruling, never hide growth or drop guarantees. Update placement/system map for moved responsibilities. |
| Evidence | Reuse scorer goldens, Raw/fuzz, transaction/race, TLS workflow, CLI/MCP matrix, restore/version/trust and locked-mock UI tests. Add actual outcome/rejection/unchanged-state tests for missing edges: concurrent revision, duplicate request, timeout-after-commit, due catch-up, auth/stream/cache races. Changed-package race/frontend tests in batches, normal hooks/CI once per candidate, no bypass; reviewer trace and live screen checks on same candidate. |
| Speed | Home broadband, desktop or modern phone, **one 32-team league**. Measure warm/cold click-to-visible and click-to-confirmed over real tunnel; report sample count, p50/p95/p99/max and every breach. Spinner/local feedback is not confirmation; no higher limit invented. Historical 31 s refresh / 3 min startup are operator observations, not new measurements. |
| Resolved Sol/Tom differences | Adopted Tom wins: two files/cadences, early digest seed + recomputation, small cutover before cache/PWA, explicit solo provisioning + local target + pinned TLS, simple topics, EventSource, one OpenRC job, step-2 memory gate, RTT first. R5b supersedes older mandatory commissioner TOTP. No pending architecture vote on these. |
| Remaining recovery tension | Tom's daily evidence manifest alone cannot establish the R4 15-minute recovery guarantee for newly referenced evidence; raw content objects alone also do not establish recovery of observations/identities/fetch chronology. Step 2 must demonstrate a matched recoverable dependency set; if daily-only metadata cannot do so, escalate the precise cadence/checkpoint adjustment before admitting writes, not silently weaken full-history recovery. |
| Remaining physical limits | Local-folder recovery cannot survive loss of its host/disk unless the chosen folder is independently protected. Tunnel RTT may itself exceed 100 ms. Measure and report these limitations; neither is permission to claim off-host recovery or relax R3/R4. |

Older diagrams/runbooks are not authority where they disagree: five-minute snapshots ≠ fifteen-minute RPO; four-hour restore remains a target until drilled; memory eviction never discards durable evidence. This document governs the client/server migration without reopening unrelated engine decisions.
