# What the commissioner/owner sees

**Draft-room undo: plain-word spec**

The commissioner sees an **Undo last draft-room change** action beside the change just recorded. Before confirming, the room names the exact change and the state it will restore. After confirmation, the room shows the restored pick/order/clock, identifies who undid it and why, and adds a visible correction to the draft history. Tell the affected owner directly and show the correction to all owners in the draft room; do not silently erase the original event. This is a recommendation, not current behavior: the catalogue says these seven commands have previews but no declared undo rule, and its undo metadata is not itself a tested reversal (`docs/architecture/catalogue-preview-undo.md:14-21`).

**Recommended safety rule:** an undo is commissioner-only and available only for the most recent draft-changing event, until another draft-changing event depends on it. Require a reason and show the exact before/after state in preview. Never undo an unrelated trade. If a trade during the draft changes who owns a pick, refuse an undo that would restore a stale owner or overwrite later picks; show the commissioner the conflict and direct them to the existing draft correction/checkpoint tools. The code already identifies picks by their original franchise, round, and extra-pick index, and makes a changed selection name the player it replaces (`internal/commissioner/draft_wire.go:301-349`). This is a proposed limit to keep the correction safe, not a rule documented in the official rulebook.

In practice: for a pick entered for the wrong team, stop the clock, undo the last selection if it is still the latest draft change, then enter the right selection and announce the correction. For a clock skip, undo the skip only if no later draft action has landed; otherwise use the commissioner’s existing draft correction process and record why. If a trade happens mid-draft, preserve the trade and re-evaluate the affected pick under its new owner; do not roll the draft back across the trade. The rulebook specifies draft contract terms, a 15-selection team limit, and forfeiture of picks beyond 15, but does not specify a live-pick correction or undo procedure (`docs/league-rules/Official_Rulebook.md:299-327`). So these operating practices are recommendations, not claims about the league's current written rules.

## `draft.pick` for owners: preview, undo, recommendation

The catalogue lists `draft.pick` as having neither preview nor undo (`docs/architecture/catalogue-preview-undo.md:14-17,25-28`). In the native catalogue, it is execute-only and uses the owner's `DraftPickInput`; server-side handling fixes the slot and contract (`internal/commandcatalog/native_mutations.go:178-181,238-239`). The draft command validates that a pick has a franchise, player, season, round, slot, and contract (`internal/commissioner/draft_wire.go:162-175`).

**Recommendation:** add a confirmation preview before an owner's pick is submitted, showing the team, round/slot, player, and contract; allow the owner to cancel before submission. Do **not** offer owners a post-submit undo: it could affect the live clock and every team behind them. Offer a short correction request to the commissioner instead, and let the commissioner apply the same guarded correction process above. The official rulebook sets rookie contract terms and draft limits but says nothing about owner undo (`docs/league-rules/Official_Rulebook.md:299-327`). Whether the existing interface has a suitable pre-submit confirmation is unknown.

## How undo is declared today; reuse this pattern

Undo is catalogue metadata on a command declaration, not a new command framework. Native mutations default to `Modes: {preview, execute}` and `Undo: "checked-reversal"`; special cases replace that value with `"none"` (`internal/commandcatalog/native_mutations.go:168-190`). The catalogue report explicitly warns that this metadata declares a rule but does not prove the reversal is tested (`docs/architecture/catalogue-preview-undo.md:20-22`).

For an existing concrete example, account-setting commands declare their undo behavior as a short named rule such as `replace-own-account-preference` and `replace-own-account-snooze` (`internal/commandcatalog/account_workflows.go:19-25,29-35`). Draft commands are presently set to `none` by the draft-family condition in `nativeMutation` (`internal/commandcatalog/native_mutations.go:186-190`). Build should update those existing declarations to the agreed named rule(s) and implement/test the corresponding guarded reversal in existing draft handling. No new framework is proposed.

Existing undo is catalogue metadata rather than tested proof, so these behavior tests are essential (`docs/architecture/catalogue-preview-undo.md:20-22`).

## Open questions for Christopher

1. Should the undo window be **only the latest draft event** (recommended for safety), or should a commissioner be able to undo an older event after later picks?
2. Should undo authority be **commissioner only**, or include co-commissioners? The listed commands currently use `command:<command-id>` permission metadata (`docs/architecture/catalogue-preview-undo.md:42-50`).
3. After an intervening trade changes pick ownership, should the system **always block undo** (recommended), or let a commissioner resolve the conflict through an explicit pick correction?
4. Should every undo require a **written reason visible to all owners**, or should the reason be commissioner-only while the correction itself is public? The official rulebook does not specify a correction-notice rule (`docs/league-rules/Official_Rulebook.md:299-327`).
