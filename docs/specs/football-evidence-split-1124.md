## Proposed split

- **Shared season part:** key by a content digest for a specific NFL season/version, not season number alone. Hold league-neutral NFL schedule, canonicalized football/player facts, and raw official weekly/play-by-play stats and their immutable revisions. The digest prevents separate snapshots or corrections from being treated as the same version; the existing body loader verifies its digest and rejects changed bytes (football_evidence.go:46-66). Build/fetch once in the server/reference store; the schedule and official stats already have server-level inputs, while the audit identifies duplicated evidence build/pin work (TOM-REPORT-shared-facts-audit.md:17-19,28-30).
- **Small league part:** retain the commissioner's approved reference/version choice plus MFL-id-to-canonical-player mapping and any MFL-derived/player fields that cannot safely be made canonical. Keep league-local identity and source provenance here. Current `BuildFootball` derives identities and facts from a commissioner's MFL player list, so simply moving the full `Players` map into a global body would be unsafe (mirror.go:137-155; football_import.go:36-48). Exact canonicalization/mapping contents need a domain decision; do not guess which MFL ids align across leagues.
- **Where built/cached:** separate the reference-store shared-season builder from league refresh; league refresh should build only its mapping/approval part and point to the selected shared digest. At request/startup, load/validate the shared digest once, then combine the small league part for the league store. Today `LoadFootball` reads/verifies/decodes one body (football_evidence.go:46-66), and `leaguePins` caches one immutable decoded object per digest for same-version league pins (football_pins.go:110-125,129-157). Extend that existing digest-keyed cache to the shared part; avoid copying it into each league value.
- **Reuse patterns:** #505's official-stats keeper builds once for three leagues on the same football digest, does separate work for separate versions, and preserves a commissioner pin made during the pass (official_stats_group_test.go:76-105). Reuse that version grouping and race-safe “do not overwrite new commissioner choice” behavior. The #496 decoded-copy pattern is already present as `leaguePins.football[digest]`, immutable and shared in memory for leagues on one digest (football_pins.go:44-47,110-125). The report's grep for literal `footballVersion`, `FootballVersion`, or `decodedCache` found no matching source symbol; the concrete patterns are these digest-based implementations.

## Risks

1. **League-scoped player ids/facts hiding in `Players`: confirmed.** The map is keyed by MFL player id; builder emits `mfl.` identities and constructs facts from each MFL player list. This requires league-local mapping or canonicalization before sharing (mirror.go:141-155; football_import.go:34-55). The audit independently flags MFL-only identities as unverified league-specific content (TOM-REPORT-shared-facts-audit.md:33-34).
2. **Scoring rules: not embedded in this body, based on checked definitions.** The body includes raw weekly stats/play-by-play and player facts, not a fantasy scoring configuration; the audit says rules are applied at read time (football_import.go:24-31; football_stats.go:22-29; TOM-REPORT-shared-facts-audit.md:4,20). Tests must still prove the new shared path leaves each league's scoring unchanged.
3. **Roster settings: no roster configuration field appears in the checked evidence struct or `leagueweek.Week`/`Game` types (football_import.go:24-32; week.go:13-21).** The commissioner audit says this evidence is not a fantasy roster (football_import.go:22-23). This rules out those specific structs, not every possible indirect league-specific value; audit all consumers before implementation (unknown).
4. **Schedule and commissioner-approved revisions:** a schedule correction or official-stat correction must create a new shared immutable version; existing approvals must remain held. The current official-stat path explicitly keeps earlier revisions and writes only when content changes (football_finals.go:45-52,79-99). Keep leagues on their existing digest until explicitly advanced (accounts/server_file.go:152-168; TOM-REPORT-shared-facts-audit.md:30).
5. **No validated performance estimate yet.** The audit says per-league memory cost is unmeasured (TOM-REPORT-shared-facts-audit.md:39); do not promise a percentage reduction.
