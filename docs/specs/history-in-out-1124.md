# GATE part 4 — history in and out

## What the commissioner/owner sees

Today, a commissioner can point TWR at an MFL archive folder and import its saved JSON exports into TWR's raw fetch archive. They see a count of files read, newly recorded, already held, and MFL error responses; repeating the import is safe and a malformed archive is rejected before it records any files. This is a data-source import, not a wizard that reconstructs league history in TWR's native league ledger. ( `internal/app/sources/api.go:149-165,216-226`; `internal/app/sources/archive.go:24-46,51-65`; `internal/ingestion/leaguearchive/import.go:56-86`; `internal/app/sources/data_sources_api_test.go:54-80,84-110`.)

For a native TWR league, champions can be kept in its opening snapshot and carried forward at rollover; the native read layer can show published head-to-head games and scored results. But those features do not yet mean a commissioner can import several old ESPN/MFL seasons—with their full historical matchups, standings, and rosters—through a guided workflow. Native roster history explicitly refuses dates before its starting observation. ( `internal/commissioner/native_seed.go:17-30`; `internal/commissioner/rollover_carry.go:47-62`; `internal/commissioner/native_results.go:15-32,74-93`; `internal/commissioner/native_reading.go:60-74`.)

There is already a command-line encrypted export for a **native TWR league**: it saves and checks an encrypted copy, can include pinned football evidence for past seasons, and does not move authority. That is meaningful full-league portability groundwork, but it is not an ESPN/MFL history export or a polished commissioner-facing download flow. ( `cmd/twr/transfer.go:25-43,46-94,97-119,122-140`.) The gate calls for importing champions, records, head-to-head and old rosters from both ESPN and MFL, plus full league export; it specifically says the import wizard follows a solid, tested engine. ( `docs/research/icp-1122/RULINGS-part5-1122.md:88-93,108-112,132-134`.)

## Gaps

- **Champions:** Native leagues already store and archive champions, but historical import from MFL/ESPN into those records is not established. The required import of past champions is explicit; external-source mapping and verification are unknown. ( `internal/commissioner/native_seed.go:17-30`; `internal/commissioner/rollover_carry.go:47-62`; `docs/research/icp-1122/RULINGS-part5-1122.md:88-91,108-112`.)
- **Records/season standings:** TWR has native league readings, but no inspected MFL archive import turns historical standings/records into native season records. The required imported records are explicit; supported source fields and mapping are unknown. ( `docs/research/icp-1122/RULINGS-part5-1122.md:88-93`; MFL archive imports fetched source bodies per `internal/ingestion/leaguearchive/import.go:56-77`, rather than a demonstrated native-ledger history conversion.)
- **Head-to-head:** Native code represents current published games/results. Historical ESPN/MFL matchup extraction, score normalization, and insertion into native season history are unknown/not found. ( `internal/commissioner/native_results.go:15-32,74-93`; requirement: `docs/research/icp-1122/RULINGS-part5-1122.md:88-91`.)
- **Old rosters:** Current native snapshot supports a starting roster observation, but cannot read roster history from before that observation. A tested importer for per-season/per-week old rosters is not established. ( `internal/commissioner/native_reading.go:60-74`; requirement: `docs/research/icp-1122/RULINGS-part5-1122.md:88-91`.)
- **Full export:** Native transfer already carries event history and selected evidence in an encrypted file with replay validation. Missing/unproven for the gate: whether this covers every commissioner/owner-visible league record and attached history artifact, any MFL-companion export, a human-facing flow, and restoration across versions. Do not call those covered based on the CLI alone. ( `internal/leaguetransfer/transfer.go:26-66,79-113,135-154`; `cmd/twr/transfer.go:25-43,46-94`.)
- **ESPN:** No ESPN historical league importer is evidenced by the requested search: ESPN-related Go matches include live-game/news ingestion, not a private fantasy-league history importer. Private ESPN access and available history fields remain unverified. The ruling requires ESPN history and schedules an ESPN import for December. ( `internal/ingestion/livegame/espn.go` (line range not inspected); `docs/research/icp-1122/RULINGS-part5-1122.md:88-93`.)

**Invariant for the build:** One common build and canonical native ledger for every league; imported MFL/ESPN data becomes ordinary league records, not a source-specific operating mode. Keep MFL companion/source settings distinct from native history; no behavior branch based on “imported from MFL” or “imported from ESPN.” Do not import or model real-NFL contract data as fantasy league history. The product rulings distinguish MFL-as-record companion leagues from TWR-as-record native leagues (`docs/reset/BUILD-PLAN.md:47-53`; `docs/research/icp-1122/RULINGS-part5-1122.md:5-9`); no real-NFL contract data is a hard rule from the task brief.

## ESPN access check plan (read-only; not run)

Purpose: learn what the private league API actually returns before designing an importer. ESPN account access and the exact historical data available are **unknown**; the plan below is a probe, not a claim that all these views work.

1. Have Christopher sign in to the intended ESPN fantasy account and select the private test league. Record the league ID, league type, and a few seasons that should be available. Do not probe a real league without permission.
2. On a trusted local machine, obtain the authenticated `espn_s2` and `SWID` cookies from that signed-in session. Treat both as credentials: never put their values in this report, source control, shell history, screenshots, logs, or a shared run folder. Use an approved secret-handling method and keep values in memory only as far as practical.
3. Issue **GET only** requests to ESPN's fantasy football league endpoint for each target season, using the league ID and those cookies. Probe small, separate requests for league settings/teams, rosters, schedule/matchups, and standings; record URL shape, HTTP status, response schema, season coverage, and redacted field names. Do not use POST, PUT, PATCH, or DELETE; do not change league settings, roster, or activity. Endpoint/view availability is to be confirmed by the response, not assumed.
4. Check whether historical roster snapshots, final scores, playoff brackets/champions, season records, team identity/name changes, and scoring settings are present and internally consistent. Compare one season to what Christopher can see in ESPN's own read-only UI. Note missing fields and any pagination/season limits.
5. Save only sanitized schema/field inventory and conclusions—no cookies, owner personal data, or full private payload—in the approved project research home. Revoke/sign out the session when finished. If the API disallows access, stop at the read-only UI evidence and record “unknown”; do not bypass access controls.

**Pass condition:** repeatable GETs return enough attributable season data to map the required champion, record, matchup and roster facts, and a manual UI comparison agrees for the sampled seasons. Otherwise ESPN import scope remains unknown and the importer must fail closed rather than invent records. The read-only requirement for ESPN market study is explicit in the rulings (`docs/research/icp-1122/RULINGS-part5-1122.md:34-35`).

## Build plan (PR-sized lanes)

All lanes retain the native ledger as the record. MFL source/import configuration is only configuration; imported history should be normal league events, with provenance retained, not source-conditioned code paths. The owner-visible import wizard comes after its foundation is solid and tested. ( `docs/reset/BUILD-PLAN.md:47-53`; `docs/research/icp-1122/RULINGS-part5-1122.md:132-134`.)

1. **MFL history adapter and ledger mapping.** Start with an inventory of actual MFL archive exports/fields and use the existing archive parser. Define explicit mappings for teams/identities, seasons, final standings/champion, weekly matchups/results, and roster snapshots; validate and preview before any ledger write. Keep missing/ambiguous rows visible and reject inconsistent seasons. **Proving test:** fixture archive covering multiple seasons imports to ordinary ledger events; replay produces expected champions, records, H2H and roster-as-of views; reimport is idempotent; malformed/incomplete input leaves ledger unchanged. Existing archive tests provide patterns for idempotence and all-or-nothing validation (`internal/ingestion/leaguearchive/import_test.go:95-143`).
2. **ESPN private-history adapter.** After the access check, implement only verified GET-derived fields, season pagination and ESPN identity matching; preserve raw-source provenance and report unsupported/missing fields. Do not build around guessed API capabilities. **Proving test:** sanitized captured response fixtures for each supported season parse to the same canonical history fixture as MFL; missing fields/unknown response versions fail clearly; no network writes are possible in the importer. Gate scope: `docs/research/icp-1122/RULINGS-part5-1122.md:88-93`.
3. **History ledger/read surfaces.** Extend the canonical history model only for what lanes 1–2 can prove; provide season trophy/champion, records, head-to-head and roster-as-of readings. Native existing H2H and champion behavior is reusable, but do not claim pre-observation rosters exist (`internal/commissioner/native_results.go:15-32,74-93`; `internal/commissioner/native_reading.go:60-74`). **Proving test:** import a two-season fixture; query each surface at a chosen season/week; compare every displayed value to source fixture and replay after restart. Then add the owner-facing wizard, with preview, confirmation, progress, and actionable per-season errors.
4. **Full league export contract and recovery.** Audit the existing encrypted native transfer against the full product promise, then add missing native history/artifacts and, if required by Christopher, MFL companion export without changing source authority. Document key handling and prove export/check/import recovery before exposing a UI. **Proving test:** export a league containing imported history, verify encrypted file, import into a clean destination, replay all history/readings and compare champion/records/H2H/rosters; test wrong key, truncation, missing evidence and interrupted import. Existing coverage: `internal/leaguetransfer/transfer_test.go:182-430`; `internal/leaguetransfer/import_test.go:46-100,176-237`.
