# SESSION D — Communication, Calendar & the Command Layer · RUN 2

You are the conceptual design lead for "TheWarRoom" — a 32-team dynasty fantasy-football command console (Go + Wails desktop, React + Tailwind, dark-only, desktop-first). The design target is Anduril, not SaaS: a command console that costs more than a house. Dark, precise, data-dense without a pixel of waste. Confident hierarchy. Controls that look like they actuate real hardware. The UI communicates capability before the user clicks anything.

You have creative latitude and you are expected to use it — push past tired dashboard/inbox/calendar patterns. But two rules bind you: (1) the locked context below is LOCKED — Sessions A, B, and C are CONFIRMED and are not yours to redesign; if you believe a locked decision is wrong, write a RIPCORD ITEMS section stating the decision, your objection, and your alternative — do not design around it silently. (2) Ground every proposal in the real surfaces and real data shapes below — no invented features.

Technical floor: WebKitGTK webview (motion = transforms/opacity only, cheap compositing — no heavy filters/blurs on large surfaces; the Beelink APU compositor has locked up on expensive paint), CSS custom properties carry ALL tokens, virtualized lists, Tailwind-expressible, pointer events (not mouse) for drag on the Linux webview.

Standing architectural fact: a future Chat engine will have COMPLETE control of this application — a terminal over a Guix-style simple command language, with a lightweight LLM router. Every mechanical control maps to a command verb (the **Command Ledger**, `docs/ui/wireframes/Command_Ledger.md`). You are NOT designing the chat ENGINE this session — you are designing its VISUAL HOME and the event/calendar surfaces it will one day drive. Nothing you propose may be impossible to express as a verb.

Standing design law — the spectrum commitment: this one product must delight a 1–2-league casual AND a 15–25-league portfolio manager. (1) light, snappy, speedy — every control acknowledges in <100ms, motion is feedback not decoration; (2) layered engagement — every surface reads at three altitudes (glance / operate / interrogate), depth DISCOVERED never demanded; (3) configurability lands as one-click presets, never toggles to study. **This session is where the spectrum commitment is most load-bearing:** attention/notification design must serve the casual (calm, no notification anxiety, the league is a pleasure not a job) AND the operator (triaged "what needs me NOW" across 25 leagues) with ONE grammar. If a proposal serves one end by taxing the other, redesign it.

## Locked context — Session A CONFIRMED spatial system (build ON this)
- **Base unit 4px.** Scale 4›8›12›16›24›32›48›64. No off-scale values.
- **Fixed 4-column instrument shell:** nav rail 192px / fluid workspace / contextual inspector (fixed **320px** `transform: translateX` overlay) / **comms right-edge 48px idle strip that summons OVER at 320px**. **Calendar summons as a generous top-right overlay.** Both comms and calendar are quick-dash — **summonable/collapsible from ANY screen** (Ledger A10 `ui.summon target=comms`, A11 `ui.summon target=calendar`).
- **Elevation optical only:** 1px hairline borders + inset bevels. NO dropshadows/blurs. Raised tile = 1px inset top/left highlight; `:active` = 1px bottom/right inset (depressed micro-switch).
- **Density tiers Narrative(48px) / Tactical(32px, default) / Matrix(22px)** ride CSS custom properties ONLY. No "Pro Mode" toggle ever.

## Locked context — Session B CONFIRMED component language (build ON this)
- **Type:** Inter = text, JetBrains Mono = data. Hero numeric 24px/700 tabular-nums. Section labels 11px uppercase 0.05em.
- **Delta-in-weight:** +Δ font-weight 600 / −Δ 400 — greyscale-honest, hue only reinforces.
- **Row grammar:** no vertical gridlines; 4 states rest / hover(raised inset) / selected(2px left axis) / active(pressed inset).

## Locked context — Session C CONFIRMED color & atmosphere (build ON this — you consume these tokens, you do not redefine them)
- **Base = cold CIC navy.** `--surface-canvas hsl(220,20%,6%)` → sunken 4% → tile 9% → raised 11% → overlay 13%. Optical elevation only.
- **Semantic layer LOCKED, one meaning each:** green=elite/positive, blue=good/info, amber=warning/watch, red=danger, gray=muted. Ramps `--signal-{green,blue,amber,red}-{muted,base,loud}` already valued (green-base hsl(145,45%,55%), blue-base hsl(210,60%,62%), amber-base hsl(35,60%,58%), red-base hsl(0,55%,62%)).
- **Restraint doctrine — "Color is Data and State. Structure is Achromatic."** NEVER tint a row/tile/canvas by value. Chrome is gray. This binds your event/chat/calendar surfaces HARD: a 40-event feed and a full month grid must NOT light up like a Christmas tree.
- **Score→hue banding** on Adjusted Score only. **Matrix yields all hue to `--text-primary` except red-danger.**
- **Focus = blue inset** (`--edge-focus`), **selection = neutral 2px text-primary axis** (`--edge-selection`). Never amber-focus (amber is semantic).
- **Freshness composed:** `--edge-freshness-live` (blue 1px) / `-stale` (amber-muted 1px) / `-failed` (red-loud 2px) + timestamp recolor + `(cache)`/`(offline)` suffix. **Guardrail: freshness chrome NEVER washes out the data itself.**
- **Motion doctrine:** transforms/opacity only, ≤150ms, FEEDBACK not decoration. `--motion-multiplier:0` in Matrix kills all of it. Named cases already defined: feed-arrival (translateY 8px→0 + fade), hold-to-fire (scaleX fill), engine-reject (opacity red flash), clock<1hr (amber timestamp tick).
- **Position badges** categorical, OFF the 5 semantic hues (QB violet 290 / RB magenta-rose 330 / WR teal 175 / TE indigo 250 / DL slate 220 / K achromatic).
- **C2 pre-wired for YOU:** Session C set the COLOR of escalation (amber→amber-loud clock under 1hr; red-loud snipe/danger). **Session D owns the event-visibility GRAMMAR that fires those colors.**

## Facet map — real surfaces & data shapes this session must honor
- **Feed / Pulse events (live):** a bid clock crossing under 1 hour, a trade offer arriving, a waiver processing, a snipe alert (danger), a commissioner announcement, a system alert (MFL fetch failed). Each has a timestamp, a severity, a subject (player/franchise/league), and — sometimes — a required action.
- **Chat / Comms (right-edge summon, 320px):** the future terminal's visual home. Messages, but ALSO cards: a **/offer trade card is a control surface living inside the conversation** (Accept / Counter / Decline are `txn.commit`-gated controls in the thread). System answers to typed commands land here too.
- **Calendar (top-right generous overlay):** the league's real deadlines — waiver run, trade deadline, franchise-tag window (§6/§9), signing window open/close (§6 UFA calendar), draft, playoff dates, season rollover (§14). These come from the **append-only `session/league-calendar` backend** (event-sourced: `EventCreated` / `EventSuperseded` / `EventUndone` — a move is an APPENDED superseding revision, never an in-place mutation; see the gcal-mechanics digest §8).
- **Cross-league reality:** the 25-league operator sees events from many leagues at once. v1 designs the SINGLE-league surfaces cleanly and LEDGER-FLAGS the cross-league aggregation seam (do not fully build multi-league; leave the seam honest, like Session A's Phase-3 injection seam at nav y=160).
- **Real data states:** an event that just fired (live), a stale feed (cache), a failed refresh (offline) — the freshness grammar from Session C must ride the event surfaces behaviorally (WHEN a surface goes stale, how a stale event reads).

## Your charge — Session D (answer with COMMITTED structures, named tokens, real anatomy)
Deliver three things, coherent as ONE system:

1. **THE UNIFIED EVENT GRAMMAR.** feed event / chat message / trade card / calendar deadline / system alert are ONE visual hierarchy — not five bespoke widgets. Define: the shared **event-row/card anatomy** (severity spine, subject, timestamp, optional action affordance); the **escalation** rule (event-driven visibility — a bid clock under 1hr rises, a snipe demands; use the C2 colors, add the STRUCTURAL treatment: order, weight, a persistent rail marker, NOT a modal interrupt for the casual); the **recession** rule (on expiry/resolve/acknowledge an event calms and sinks — nothing accumulates as unread-anxiety debt); how ONE grammar reads as CALM for the 2-league casual and as TRIAGED-QUEUE for the 25-league operator (altitude, not a mode toggle). Ledger-flag the cross-league aggregation seam. State how freshness rides an event (a stale event's treatment).

2. **CHAT AS THE TERMINAL'S VISUAL HOME.** Design the thread grammar where a typed command, a system answer, a chat message, and an actionable card (the /offer trade card) all live in ONE scannable thread. Define: the message/card row anatomy in the 320px comms column; how a **control surface inside the conversation** (Accept/Counter/Decline on a trade card) looks and routes (through the B ConfirmModal); how a typed command and its system answer are visually distinguished from human chatter; the input affordance (this is the future terminal's prompt — it must read as a command line, not a chat box, without alienating the casual). You are NOT designing the command language or the LLM — only the visual home a command lands in. Every actionable element gets a Ledger row.

3. **THE CALENDAR — fully buildable, not aspirational.** This is "Google Calendar from inside a command console." Deliver concrete, implementable anatomy: **event-chip anatomy** (color bar = which semantic/categorical hue? title/time density per view); **views** — week / month / agenda + a mini-month navigator (per the digest §3); **overlap layout** for simultaneous events (column-share vs stack vs "+N more", per digest §2.4 — pick one and commit); **creation** — click-empty→quick-create popover + click-drag-to-create with ghost+snap (15-min grid, digest §1.1/§1.2); **manipulation** — drag-move + edge-resize with a ghost preview + snap, committing on RELEASE (WebKitGTK cheap-paint floor + Session A's release-commit rule; the digest §2.2 flags edge-resize as risky on WebKitGTK — give the "edit duration" fallback); **append-only honesty** — a dragged move commits as an `EventSuperseded` appended revision (digest §8.2), and the UI must be honest that history is preserved (an audit/undo affordance — the snackbar undo from digest §2.5 is itself another append). PLUS: the **quick-dash summon** (calendar from any screen, Ledger A11) and an **operational overlay** — deadlines appearing ON the surfaces they govern (a trade deadline badge on the trade builder, a waiver-run countdown on the transaction panel), not only inside the calendar overlay.

Every actuating control across all three gets a **Command Ledger** row (verb + args, Guix-simple) or a RETURN-SESSION flag. Motion stays inside the Session C doctrine. Color stays inside the restraint doctrine — earn every hue.

## Provocation seed for THIS run
**"THE OPS ROOM — THE COMMAND LINE IS THE SPINE."** The organizing spine is not time — it is the COMMAND. The chat terminal is the PRIMARY instrument (the future engine drives the whole app from here), and the feed and the calendar are two SUMMONED instruments the command line addresses and drives — not peers of the chat, but readouts and actuators docked around the operator's one true control surface. The unifying thread across feed/chat/calendar is the **Command Ledger verb**: every event carries the verb that would act on it, every calendar deadline is a verb that will fire, every trade card is a verb awaiting confirmation. An event is not a thing that happened — it is a thing you can ACT on, and its anatomy foregrounds the action. Push this hard: escalation is "this needs a command from you NOW"; recession is "resolved — no verb outstanding"; the operator's 25-league triage is a single queue of outstanding verbs across all leagues; the calendar is a schedule of verbs that will auto-fire (with the append-only log as the command history). The chat prompt is the spine of the entire product, and the calendar/feed are what it commands. Then be honest in RIPCORD about where the "command-first" metaphor fights the 2-league CASUAL (who wants a calm league they enjoy, not a terminal with a blinking cursor demanding input — the casual must NOT feel they're staring at a command line they have to learn), or where foregrounding "the verb" on every event clutters a surface that should sometimes just be read, not acted on.
