## Head-brain rulings — IMPLEMENT THESE (do not relitigate)

**R-A — The frame is "an Inbox that opens onto an Oracle."** COMPOSE both, do not pick. The phone is REACTIVE at the front door (push-first: escalated events + deadlines reach you) and PROACTIVE once inside (the `/`-pivot command channel returns answer-cards on demand). Neither run is the whole phone; each is one half. This is the organizing thesis of the handoff.

**R-B — Survival table: adopt Run 2's table, with Run 1's push-escalation grafted on.** M2 Power Rankings = **CHAT-ANSWERABLE** (Run 2 is right — "where do I rank?" is a natural query, not death). Home = DEAD, M1 = CHAT-ANSWERABLE, Inspector = CHAT-ANSWERABLE, Comms = LIVE CARD (the shell), Feed/Pulse = LIVE CARD, Cross-league = PUSH. **BUT the deadline/escalation axis is PUSH, not pull:** Calendar is CHAT-ANSWERABLE for browsing AND fires PUSH when a deadline escalates (<1hr / roster-lock); M4 Transaction WS is DEAD as a builder but its escalated trade/bid events arrive as PUSH → Control Card. Oracle's pull-only gap is its own admitted RIPCORD — close it with Inbox's push spine. Every surface gets exactly one primary fate + (where relevant) its escalation-push behavior.

**R-C — The one flawless flow = zero-typing, push-deep-linked.** BOTH runs converged here (Run 2's RIPCORD #2 explicitly conceded it): the under-clock flow must NOT require the operator to type a query. The escalated bid/trade push **deep-links directly into the thread with the `/offer` Control Card already expanded and rendered** — the operator opens the phone and immediately executes hold-to-fire. Query-then-act is the *proactive* path (calm state); push-into-expanded-card is the *reactive* path (under clock). Design the ONE flawless flow as the reactive path (the 11pm snipe / trade-under-clock), and show the proactive query path as the everyday counterpart.

**R-D — VAV without hover = tap-to-expand PRIMARY, swipe reserved.** Resting rows show spine + timestamp + subject + predicate, zero action chrome. **Tap-to-expand** a slide-down action drawer is the primary affordance reveal (Run 2). **Swipe** is reserved for the SINGLE highest-frequency one-shot action only (acknowledge/dismiss — Run 1), not a general action surface. Escalation FORCE-PERSISTS the affordances inline (both runs agree) — an escalated Control Card is never hidden behind a tap or swipe.

**R-E — Hold-to-fire commits inline on the card.** The 480px centered ConfirmModal is DEAD on mobile (it doesn't fit). The hold-to-fire GESTURE survives as the durable part (≤600ms fill, release-cancels, engine-reject holds). Form: the gesture lives on the Control Card's action button and **ink-fills the button/card** with the semantic hue of the action. `[COMMITTED — HH:MM]` on success; spine recedes to `--edge-freshness-stale` then the row fades to 50% (Session D recession). Routes `txn.commit action=`.

**R-F — The command prompt is NOISE-TOLERANT natural-language + VOICE input, not a canned verb picker.** (New mandate, Christopher, Session E — see `Command_Ledger.md` input-normalization note + `[[project_thewarroom_react_rationale]]`.) Real mobile input arrives FUZZY: **misspelled words** (thumb-typos) and **voice-chat transcription errors** (speech-to-text). The LLM router **normalizes fuzzy input → the canonical Command-Ledger verb BEFORE any output** (normalize-then-act; never echo the garbled token, never run a mis-parsed verb). Design consequence for the shell: the `/`-pivot input bar must present as **free natural-language / voice-first**, WITH a quick-verb rail as an ACCELERATOR (not the only path). Show a **voice-input affordance** (mic) as first-class on the prompt. Show, in the wireframe or a note, the normalize-then-act beat: fuzzy utterance → `↳ SYS` resolves to the canonical verb → card. This is WHY the backbone is LLM-backed, not a rigid parser — reflect that in the input anatomy.
