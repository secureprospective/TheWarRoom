## Gemini — received 2026-07-12

**Q1 IA:** Hybrid Player/Franchise-centric split into two zones — **Roster Management** (GM ops) and **League Office** (commissioner ops). Select Franchise → view roster → click Player → contextual action panel showing ONLY ops valid for that player's state (roster vs taxi). SIGN via a dedicated Free Agent pool view. League Office houses ADVANCE_PHASE/ROLLOVER_SEASON/SET_SIGNING_WINDOW/CAP_RELIEF; RETIREMENT/DEATH sit in the player panel under a group-isolated "Commissioner Overrides" sub-header. Conf 9/10.

**Q2 Entry point:** Franchise Matrix Dashboard (light 32-franchise grid: owner, cap used, roster count) + persistent Global Player Search. Path A: click franchise → click player → panel (2 clicks). Path B: type name → click result → panel. Conf 8/10.

**Q3 Name resolution:** Two enriched Go reads (don't stitch from GetRankings on the client):
- `GetEnrichedFranchiseState(id) → {franchiseName, capUsed, players:[{mflID,name,position,rosterStatus,salary,capSalary}]}`
- `GetEnrichedFreeAgents() → {players:[{mflID,name,position}]}`
- `GetFranchiseDirectory() → [{franchiseID,franchiseName}]`
Discovery: (1) browse enriched roster, (2) global search hooked to a Zustand index populated once on boot from GetRankings (zero-IPC typeahead). Conf 9/10.

**Q4 Confirm flow:** Two-phase **dry-run quote → commit** via a `preview: true` bool on the EXISTING `ExecuteTransaction`. Backend runs the exact logic in a SQLite savepoint, returns the receipt with server-computed price WITHOUT committing; frontend shows a mandatory confirm modal with exact financial impact; confirm re-fires the identical payload with `preview:false`. Trade-off: backend needs a non-committing execution path, but no calc duplication and both invariants preserved. Conf 9/10.

**Q5 Commissioner vs GM:** System-wide admin (ADVANCE_PHASE, ROLLOVER_SEASON, SET_SIGNING_WINDOW, CAP_RELIEF) live ONLY in a League Office tab, absent from roster views. Player-specific overrides (RETIREMENT, DEATH) sit in the player panel in an isolated bottom section ("League Office Overrides", distinct border). Role-flag hideable later. Conf 8/10.

**Q6 Session scope:** **Single-Franchise Enriched Roster View + Player Action Sheet.** Includes GetEnrichedFranchiseState, a flat 0px-radius roster list (names/positions/salaries), the sliding contextual action panel, three core ops wired (ROSTER_STATUS toggle, WAIVER/cut, RESTRUCTURE), and the confirm-modal mechanism. Highest-frequency ops, establishes the player-centric pattern + staging pipeline, no throwaway. Conf 9/10.

**Q7 Risks:** (1) WebKitGTK heavy-list / null-unmount crash on AMD APU → defensive render guards (fallback states not throws), flat tables, virtualize/paginate the FA pool + search. (2) Phase-locked state desync (stale phase → confusing post-confirm rejection) → central phase validation from GetCurrentPhase(); every action button passes a client-side phase gatekeeper, disable + inline "Available in Offseason Only" reason. Conf 9/10.

## DeepSeek — received 2026-07-12

**Q1 IA:** Player-centric, phase-filtered, + a commissioner section (NOT op-centric, NOT a split layout). Every op except ADVANCE_PHASE/ROLLOVER_SEASON involves a player; starting from a player constrains legal ops (phase × roster status × eligibility). Shape: left sidebar = 32 searchable franchises → center = sortable roster table (names/pos/salary/cap/status) → right slide-in panel on player click shows player detail + ONLY phase-legal action buttons (14 → ≤4-6 visible per player). TRADE = its own full-screen modal/tab (only multi-franchise/multi-player op). Commissioner ops in a ⚙ Admin dropdown. Header = prominent color-coded phase badge + global search + Admin. Conf High.

**Q2 Entry point:** Franchise roster view, default to last-viewed or ARI. Most common action = sign a free agent (waiver processing) or roster-status toggle (taxi activation) — both player-centric. 3 clicks (franchise → player → action → confirm); 2 via global search. FLAG: if waivers are processed in batches (15 claims/sitting) the 3-click-per-player model fatigues — a batch/checklist fast-path may be needed later; not first-pass. Conf High on entry, Medium on batch need (unstated volume).

**Q3 Name resolution:** New read IPC (all read-only, cheap):
- `GetFranchiseDirectory() → [{id,name,abbreviation,division}]` (fetch once, cache)
- `GetRoster(franchiseID) → {capUsed, players:[{mflID,name,position,nflTeam,rosterStatus,salary,capSalary,yearsRemaining,franchiseTag,extensionYears}]}`
- `GetFreeAgentPool() → {players:[{mflID,name,position,nflTeam}], count}` (no salary/status — FAs have none)
- `SearchPlayers(query) → {results:[{mflID,name,position,nflTeam,franchiseID|null,franchiseAbbr|null}]}` (rostered + FA)
Discovery both paths: primary = via franchise roster (team-centric mental model); power = global search (name-known, team-unknown), fuzzy, ≤15 results, 200ms debounce, navigates straight to player detail. Cache directory + FA pool in Zustand; roster per-franchise on select. Conf High.

**Q4 Confirm flow:** Two-phase **Quote → Confirm → Commit** with a NEW `PreviewTransaction(req) → {ok,kind,playersAffected:[{mflID,name}], breakdown:{capHit,capHitYears,deadCap|null,resultingCapSpace}}` — same req shape as ExecuteTransaction, pure in-memory, no WAL write. Flow: pick player+op+params → Quote fires Preview → modal shows the big number ("Tag C.Lamb: $18.2M cap hit, 1yr. Resulting cap space $3.1M") → Confirm & Commit fires ExecuteTransaction → receipt. **Exception: ROSTER_STATUS (costless) skips preview**, straight to a plain confirm — determined client-side by whether the op kind has a financial change. Conf High on two-phase, Medium on exact breakdown shape (match what the engine naturally computes).

**Q5 Commissioner vs GM:** ⚙ Admin dropdown in the header chrome (permanent home for all 6), quiet — no badge/dot. ADVANCE_PHASE/ROLLOVER_SEASON/SET_SIGNING_WINDOW/CAP_RELIEF live only there. RETIREMENT/DEATH ALSO appear as shortcuts below a divider in the player detail panel, red/danger "Commissioner Actions", only when Admin/commissioner mode is active. Rejects a dedicated tab/mode (adds a context switch); dropdown = 1 click away but visually quiet. Conf High.

**Q6 Session scope:** **Franchise Roster + ROSTER_STATUS + WAIVER(cut) + SIGN + confirm flow.** Ships: 3 read IPCs (Directory/Roster/FreeAgentPool), PreviewTransaction (fully wired for these 3, stubbed elsewhere), franchise sidebar, sortable roster table, slide-in player panel (phase-filtered), 3 ops wired (ROSTER_STATUS plain-confirm / WAIVER preview-shows-dead-cap / SIGN salary+term form → preview), shared confirm dialog, phase-aware filtering (illegal ops don't render). Usable = commissioner does the daily waiver/roster job with real names + cap. If time tight, trim SIGN, keep ROSTER_STATUS + WAIVER. Conf Medium-High (Go IPC-registration effort is the unknown; ~4-6h if the bridge is well-structured).

**Q7 Risks:** (1) WebView DOM fragility (technical): 53-row table re-renders + empty-roster null-map → root unmount (the past bug) → virtual-scroll (react-window, ~15 rows), NEVER render null (`rows={players ?? []}` + `<EmptyState/>`), memoize rows, cache directory. (2) Feature creep / overbuilt IA (UX): layers accumulate into a prettier wall of options → ship the minimal slice and USE it before adding; ONE canonical path (search is additive not competing); reject future-proofing this session ("don't paint out GM-per-team" = don't hardcode permissions, NOT design multi-user now); usability-test a real batch (5 claims / 3 cuts / 2 signings). Conf High.

## hy3 — received 2026-07-12

**Q1 IA:** Entity-centric GM workspace + quarantined Commissioner zone + phase-aware op-filtering. Default "Transact" tab: pick working franchise → roster with names → select player → contextual action RAIL (right sidebar) with only phase-legal ops (rostered non-tagged → TRADE/ROSTER_STATUS/WAIVER/TAG/EXTENSION/RESTRUCTURE/BUYOUT; FA → SIGN); illegal ops ABSENT not greyed. "Commissioner" tab for the 6. **Top phase strip: current phase + ADVANCE_PHASE + SET_SIGNING_WINDOW surfaced there because they gate everything.** Conf High on entity-centric; Medium on default-franchise UX (brief doesn't say how the operator picks "their" team when doing everything).

**Q2 Entry point:** Roster of the active working franchise + one-click "act on this player" + FA pool one swap away. **HONEST FLAG: the #1 op is NOT stated in the brief — a gap to close with real usage before betting the layout on it.** Safe path: select player (1) → 2-3 surfaced high-freq ops (1) → confirm (1) = 3 clicks. If forced to guess #1: SIGN + WAIVER recur most; trades high-salience but lower-frequency → surface SIGN/WAIVER/TRADE on the top rail. Conf Medium on path, Low-Medium on which op is #1.

**Q3 Name resolution:** Enriched reads + one directory: (1) enrich GetFranchiseState players with name+position; (2) enrich GetFreeAgents → {freeAgents:[{mflID,name,position,priorSalary?}]}; (3) `GetFranchiseDirectory() → {franchises:[{franchiseID,name,abbr?}]}`. Discovery = BOTH layered: global fuzzy search backed by a cached GetRankings index (already carries name/position/franchiseID — no new data, just cache client-side) + per-franchise browse. Commissioner-does-everything → global grab-any-player essential. **Staleness caveat: a cached GetRankings index diverges if a player changes franchise mid-session → re-fetch on every ExecuteTransaction receipt + on phase change; if GetRankings is heavy, prefer a dedicated GetPlayerSearch(query) getter — triage item.** Conf High on names-from-reads; Medium on cache-vs-dedicated-search (cost unknown).

**Q4 Confirm flow:** Two-phase quote → confirm → commit. `GetQuote(req) → {price, capAfter, deadCap, legibleDetail, warnings}`, compute-only, **reuses the SAME internal compute the commit path calls (no logic duplication/drift).** Post-commit-only rejected — violates invariant 2 for the most consequential ops. **Q5 Commissioner vs GM:** Dedicated "Commissioner" tab for the 6, with ADVANCE_PHASE + SET_SIGNING_WINDOW ALSO mirrored in the top phase strip (operational, frequent, gate the league). Inside tab, group by frequency/risk: phase control (strip); ROLLOVER_SEASON (common milestone); RETIREMENT/DEATH/CAP_RELIEF buried under "Roster events / adjustments". Commissioner reaches all 6 in ≤2 clicks; later GM split = hide the tab per-team. Conf Medium-High.

**Q6 Session scope:** "Named roster + one complete staged write" vertical slice: (1) enriched GetFranchiseState + GetFranchiseDirectory; (2) roster view with names + franchise picker; (3) **ONE op end-to-end — pick SIGN**, because its salary/term is CLIENT-supplied so it needs NO quote path → the slice ships in one session AND becomes the reusable transaction shell (priced ops just add a quote step later). Conf Medium; alternative = reads-only roster (lower risk, less proof) — hy3 favors the vertical write slice.
> **NOTE — this DIVERGES from Gemini/DeepSeek on first-op choice: hy3 picks SIGN specifically to avoid building the preview/quote path in slice 1; DeepSeek picks ROSTER_STATUS+WAIVER (and builds PreviewTransaction in slice 1). Triage decision point.**

**Q7 Risks:** (1) UX wall-of-options relapse — a "prettier" op-list instead of true entity surfacing; symptom = operator still scans 8-14 per player → anchor every action on a selected player, ≤3 default ops, validate by watching a real move. (2) Technical — acting on the WRONG entity via identity confusion / stale name cache: operator confirms a silent atomic move on a mis-mapped id → single source of truth for names (server reads, NO hand-typed IDs anywhere), re-fetch index on every write/phase change, guard every list against null/empty (the unmount bug). Secondary: hardcoding "commissioner does all" into the GM workspace → isolate commissioner concerns to their tab. Conf High on both.

## GLM 5.2 — received 2026-07-12 (Beelink, Claude-driven, EXIT=0)

**Q1 IA:** Hybrid — primary "Franchise workspace" (player-centric actions) + secondary "League Controls" zone; phase as a legality FILTER inside the action panel (not a top-level navigator); commissioner-role as a future auth gate. Franchise picker rail (32 + a "Free Agents" pseudo-franchise) + global name search → roster center → click player → right panel shows only ops legal for THAT player in THIS phase. Calendar ops (ADVANCE_PHASE/ROLLOVER_SEASON/SET_SIGNING_WINDOW — no player subject) → League Controls. Subject-bearing commissioner ops (RETIREMENT/DEATH→player, CAP_RELIEF→franchise) stay WHERE THEIR SUBJECT IS, in an amber/red segregated "Commissioner" section. Rule: **an op's home is its subject; its prominence is its frequency.** Conf High.

**Q2 Entry point:** Land in Franchise workspace, default franchise selected (last-viewed or commissioner's own), roster visible, Free Agents one click away. #1 op = SIGN (~3 clicks), but Medium confidence it's SIGN vs CUT/ROSTER_STATUS — confirm with operator usage. Commissioner ops deliberately NOT front and center. Conf High shape / Medium on which op.

**Q3 Name resolution:** Enrich the two getters IN PLACE + add a franchise directory; do joins SERVER-side (keep frontend logic-free). `GetFranchises() → [{franchiseID,name,...}]` (NEW); `GetFranchiseState(id) → {capUsed, franchiseName, players:[{mflID,name,position,rosterStatus,salary,capSalary}]}`; `GetFreeAgents() → {players:[{mflID,name,position}]}`. For global search: lean a dedicated `GetPlayerDirectory() → [{mflID,name,position,franchiseID|FA}]` over client-stitching two lists (avoids join logic in React — the "no new logic in frontend" doctrine). Both browse + search paths. **Flags to verify vs source: does a franchise-name source already exist? (brief names only GetRankings as carrying names).** Conf High on need/shape, Medium on naming, Low/flag on franchise-name existence.

**Q4 Confirm flow (SHARPEST):** Two-phase quote→confirm→commit via a `dryRun` flag on the EXISTING ExecuteTransaction (or a separate QuoteTransaction — maintainer call). **CRITICAL DOCTRINE CATCH: the commit resends the same INTENT, never echoes the quoted price back as input — if the client submitted the quoted number, that number is "coming from the client," a silent violation of invariant 1. The quote is ADVISORY; the commit is AUTHORITATIVE and RECOMPUTED. If receipt ≠ quote, flag loudly.** Undo is NOT an option (brief never says the engine can reverse — assuming reversible writes is invention). Keep the quote step on for ALL ops (client-priced too) for uniform cap-impact display. **Flag vs source: does the engine already support a clean no-persist compute path, or does dryRun need non-trivial plumbing?** Conf High on pattern, Medium on flag-vs-method.

**Q5 Commissioner vs GM:** Ops live where their subject is, visually segregated; the 3 pure calendar ops get their own League Controls zone (lean a dedicated labeled zone over the catch-all Admin sidebar, so high-impact transitions aren't filed as "misc admin"). RETIREMENT/DEATH → player panel Commissioner section; CAP_RELIEF → franchise header Commissioner section. Conf High on principle, Medium on calendar-op home.

**Q6 Session scope:** Foundation = enriched read IPC + Franchise/FA workspace shell + global search + the dryRun→confirm→commit flow, proven end-to-end with **SIGN (client-priced) AND WAIVER/CUT (server-priced dead cap)** — the two together validate BOTH pricing paths through one shared flow. The plumbing (names everywhere + staged flow) IS the foundation; the ops are just the proof. If time forces a cut: SIGN + enriched reads + workspace + the dryRun mechanism, WAIVER as stretch. **"Do not ship without enriched reads — a nameless workspace is the current dev panel with paint."** Conf High on foundation, Medium on fitting both ops.

**Q7 Risks:** (1) UX — name resolution incomplete in ONE view → UI silently regresses to mflID-hell in that path (e.g. trade-builder target search reuses an un-enriched getter); avoid via a per-view name-coverage checklist + a test that no player object renders without a name. (2) Correctness/doctrine — the commit path echoes the quoted price, OR the quote path is skipped → blind commits on server-priced ops; avoid via the hard rule (commit resends intent, engine recomputes, quote is advisory-never-input) + gate shipping TAG/EXTENSION/BUYOUT on the dry-run existing. Honorable mention: empty/edge-state unmount bug class — every container renders a defined empty-state, never `return null` from a list; add an empty-state test matrix.

**GLM's 3 unconfirmed-against-source items to verify BEFORE building:** (a) does a franchise-name source already exist? (b) does the engine support a no-persist compute path for dryRun? (c) is any transaction reversal supported (assume NO until shown)?
